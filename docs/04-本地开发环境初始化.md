# Atlas 本地开发环境初始化指南

## 1. 初始化目标

本阶段先建立可重复的开发环境和服务配置，不一次性实现完整自动化。完成后应能够构建 Java 工程，并为 TTS、素材搜索、图片生成和视频渲染准备统一的配置入口。

## 2. 当前机器分工

- **电脑 A（Atlas）**：运行 Java 服务、工作流和项目文件管理。
- **电脑 B（生成服务）**：运行 ComfyUI 与 Qwen Image 2.1。
- **Doubao TTS 2.0**：复用已接通的服务端点和鉴权方式。
- **Pixabay**：由 Atlas 发起素材搜索请求。

如果 Doubao TTS 实际运行在电脑 B，可先将它视作远程服务；Atlas 只需要知道可访问的 API 地址和鉴权参数，不要求把服务迁移到电脑 A。

## 3. 配置密钥

1. 将仓库根目录的 `.env.example` 复制为 `.env`。
2. 填写 Pixabay API Key、Doubao TTS 所需的鉴权参数。
3. 确认 `.env` 已被 Git 忽略：

   ```bash
   git check-ignore .env
   ```

4. 不要把真实 Key 写入 YAML、Java 源码、日志、截图或 Git 提交。

不同版本的 Doubao TTS 接口可能使用不同的请求头、资源 ID 和请求体。编码 Provider 前，应以你当前已成功调用的接口格式为准，不要凭空假设鉴权字段。

## 4. 检查 Java 工程

在仓库根目录执行：

```bash
java -version
mvn -version
cd atlas-parent
mvn -DskipTests package
```

当前父 POM 配置的 Java 编译版本是 21，因此建议使用 JDK 21。若构建失败，先修复现有模块或依赖问题，再接入外部服务。

## 5. 配置 ComfyUI

1. 在电脑 B 启动 ComfyUI，并确认本机可访问其 Web/API 服务。
2. 默认端口通常是 8188；以实际启动参数为准。
3. 电脑 A 先测试连通性，例如：

   ```bash
   curl http://电脑B的局域网IP:8188/system_stats
   ```

4. 将 `COMFYUI_BASE_URL` 设置为可访问的局域网地址。
5. 生成图片时使用已验证可运行的 Qwen Image 2.1 API 工作流 JSON，通过 ComfyUI 的工作流 API 提交任务并轮询结果。

不要把 ComfyUI 端口直接暴露到公网。若两台电脑不在同一局域网，应使用受控的 VPN/隧道方案，并配置访问控制。

## 6. 视频输出目录约定

每个视频项目独立保存中间文件，便于失败恢复和人工检查：

```text
workspace/
└── videos/
    └── <project-id>/
        ├── project.json
        ├── script/
        │   ├── narration.md
        │   └── storyboard.json
        ├── assets/
        ├── audio/
        ├── subtitles/
        ├── render/
        └── manifest.json
```

- `project.json`：项目参数和状态。
- `narration.md`：最终旁白稿。
- `storyboard.json`：结构化分镜、画面提示词和素材需求。
- `manifest.json`：素材来源、文件路径、生成参数和校验结果。
- `render/`：最终成片及预览。

以上是约定目录；后续由代码自动创建。生成的视频、音频、图片和密钥均不应提交到 Git。

## 7. 按顺序打通最小闭环

### 阶段 A：构建与 API

- [ ] JDK/Maven 环境可用。
- [ ] `mvn -DskipTests package` 成功。
- [ ] 确认当前 REST API 的实际启动入口和健康检查方式。

### 阶段 B：语音

- [ ] 用一段 1～2 句的短文本调用已接通的 Doubao TTS。
- [ ] 将结果保存到项目的 `audio/` 目录。
- [ ] 记录请求失败原因，但不得记录 API Key。

### 阶段 C：素材和图片

- [ ] 使用 Pixabay 搜索少量素材，保存来源 URL 和授权/署名信息。
- [ ] 通过 ComfyUI 工作流生成一张测试图。
- [ ] 对超时、任务失败和无结果增加明确错误提示。

### 阶段 D：合成

- [ ] 检查 FFmpeg 是否安装：`ffmpeg -version`。
- [ ] 先将一张图片和一段音频合成为短视频。
- [ ] 再增加字幕、多个镜头、转场与音量处理。

### 阶段 E：恢复与审核

- [ ] 为每个阶段保存状态和产物路径。
- [ ] 失败后从最后成功阶段重试，而不是重新生成全部内容。
- [ ] 成片输出前保留人工审核步骤。

## 8. 推荐的 Provider 接口边界

- `TtsProvider`：输入文本、音色与语速配置，输出音频路径及元数据。
- `AssetProvider`：输入关键词和素材类型，输出候选素材及来源信息。
- `ImageProvider`：输入提示词与生成参数，输出图片路径及生成记录。
- `VideoRenderer`：输入音视频时间线、字幕和素材清单，输出成片及渲染报告。

业务流程依赖接口，不直接依赖某个供应商的请求格式。先实现并测试一个 Provider，再接入工作流。

## 9. 当前不在初始化范围内

- 不在此阶段重写已有 Java 多模块结构。
- 不把 API Key 提交到仓库。
- 不要求立刻接入 Temporal、数据库或所有发布平台。
- 不在未验证接口和工作流之前承诺端到端自动生成成功。

下一步应检查现有 `atlas-api`、Agent 与插件模块的真实实现，然后补齐健康检查和第一个可运行的 TTS Provider。
